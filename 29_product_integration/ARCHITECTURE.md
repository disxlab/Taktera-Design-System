# BR5 — ERP/CRM integration contract (proposed)
Status: reusable client-side foundation; actual host/staging not connected. Issue #12. Existing Alpha.7 is a synthetic standalone demo; do not replace approved assets or its historical QA.
## Boundaries
Host application owns identity, tenant/branch scope, roles, permissions, business rules, audit trail, locale, timezone and API transport. UI owns presentation, controlled state, keyboard/focus, loading/empty/error/stale states. UI selection is not authorization. Never store real medical/client records in localStorage, fixtures, CI logs or screenshots. All examples synthetic.
## Data contract
Use opaque stable string IDs, explicit ISO timestamps with timezone, integer minor units plus ISO currency for money (do not derive money from float); row versions/ETags for mutations. Proposed request { filters:[{column,op,value}], sort:[{column,direction}], groupBy?, page:{cursor?,limit}, scope: host-resolved }. Response { rows, nextCursor, total?, groups?, revision }; cursor opaque, sort deterministic with ID tie-breaker, server validates allowed fields/limits and derives scope from authenticated context. Query changes cancel in-flight request; ignore stale response by request sequence. Error taxonomy: validation, forbidden, conflict, rate-limit, unavailable. No raw SQL/filter expressions. Bulk actions explicit selected IDs and version per row; server rechecks permissions, idempotency and conflicts; return per-row success/failure. No implicit select-all on server data. Audit actor/action/time/result without unnecessary PII.
## AdvancedDataGrid initial scope
TypeScript query model + React accessible native table adapter with typed columns, locale text filter, multi-column sort core, exact/range filters core, grouping counts, page-window/selection, bounded virtual window math. React UI currently exposes single sort, search, grouping summaries, explicit row/page selection and pagination; optional fixed-height virtual DOM with accessible paginated fallback, explicit visible-window selection and keyboard Home/End/Page/Arrow scrolling; remote adapter, inline editing, column reorder, grid keyboard model and true grouped rows remain open. Keep native table semantics, explicit row counts and indices; screen-reader validation of virtual mode remains mandatory. Stable sorting nulls last. No new deps; CSS uses existing semantic classes. No automatic mutations.

Add remote cursor and abort/stale tests, tenant isolation/permission tests against real backend, conflict/idempotency and a11y manual checks. Staging integration remains blocked until actual host/API and test credentials are provided through approved channels.

## BR5 transport and Scheduler core
RemoteGridController uses host-injected transport, cursor limits, abort and generation checks. Bulk protocol requires explicit confirmation, ID/version, idempotency key and per-row outcomes. Actual server enforcement, remote UI and staging remain open. Scheduler core validates explicit-offset timestamps, half-open intervals, same-resource conflict and cancelled/self exclusion; DST is represented by explicit offsets. Client conflict checks are advisory; server transaction is authoritative. New QA pending.

## RemoteDataGrid UI
Host injects a stable authenticated transport; remount on tenant/session change. Cursor navigation, search, sort, explicit row/version selection and confirmation dialog; partial results retain failed IDs and require refresh/reselection before repeat. Unknown outcomes require server reconciliation, no automatic replay. Paginated local grouping uses actual group header rows; virtual mode remains flat. Browser tests use synthetic transport only.
