# Candidate release policy (BR6)
The release-evidence job runs only when all required CI jobs succeed. It gathers npm and Windows/macOS NuGet package evidence, verifies SHA-256 against consumer reports, compares packaged declarations against API contract, writes CycloneDX 1.6 consumer inventories, checksums and unsigned CI source/run evidence. It does not create a GitHub release, sign artifacts, publish npm/NuGet, or grant a license.
- SBOM scope: dependency inventories from actual npm consumer lock and each .NET consumer project.assets.json; includes consumer/tooling dependencies, not a complete product or redistributable-asset SBOM. License metadata is not asserted when unavailable.
- Review third-party notices, fonts, icons, redistribution rights, registry permissions, token scopes and package provenance before approval. Separate approved license decision mandatory; no publish credentials in PR workflow.
- API candidate guard: declaration equality against Run #24 source revision, using current locked compiler. Any declaration change requires review even if additive; this is conservative, not general semantic compatibility proof. Native tests cover resource enum/URI and runtime brush contract.
- Verify candidate SHA256SUMS.txt before installation; Windows and macOS builds may differ in bytes. No bit-for-bit reproducibility claim. Pin approved versions/lockfiles; use SDK.md for rollback. Require signed provenance, reproducible artifact policy, independent synthetic SDK acceptance and manual/native/accessibility gates before Stable.
