# Versioning & Compatibility Policy — BR7-09

Proposal for owner review. Current internal package identities remain unchanged: @taktera/ui-core 4.0.0-alpha.5; @taktera/ui-react and Taktera.UI.Avalonia 4.0.0-beta-readiness.3. Internal unsigned candidate identity is source SHA, run/attempt and archive SHA-256; same version with different bytes is never publishable as a replacement. At approved promotion all three SDKs must share a release version; proposed first Beta 4.0.0-beta.1, RC 4.0.0-rc.1, Stable 4.0.0. Increment prerelease ordinal for new artifacts after publication; never overwrite or use build metadata to evade an immutable version. Major breaking, minor backwards-compatible addition, patch backwards-compatible fix after Stable. Before Stable, document changes and migrations explicitly; no automatic promotion. Repackaging or changing private flags/versions invalidates earlier bytes and requires every gate again.

The preflight compares actual current and pinned historical archives: npm declarations and package contract fields, NuGet documented XML member IDs, assembly name, library paths and dependency groups. It detects identity collisions independently of file names. Strict equality is conservative; reviewed API changes require a new explicit baseline. XML docs are not complete CLR ABI evidence; actual binary compatibility, supported host versions, migration tests, approved release baseline and owner authorization still required. Ten negative controls and positive promotion/immutability and API mutation controls. No release version change, registry writes or production approval. Historical candidate is unsigned, not an approved release. Run #42 still in progress when authored. Next CI must confirm.

Important SemVer precedence: 4.0.0-beta.1 sorts below 4.0.0-beta-readiness.3. The proposed beta.1 is only for a first publication from unpublished internal candidates, not an upgrade from a published beta-readiness.3. Before actual publication inspect real registry version history, choose a strictly advancing version when applicable, and obtain owner approval. Added numeric prerelease and metadata precedence controls.
