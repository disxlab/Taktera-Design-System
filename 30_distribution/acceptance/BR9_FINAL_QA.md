# BR9 — final acceptance protocol

The automated summary is not release approval. BR9 includes a browser performance smoke baseline and native clean consumer elapsed time; measurements use the local loopback host and fresh Playwright contexts on shared CI runners. Proposed p95 thresholds: navigation/hydration 5 s, resolved save 2 s, native restore/build/headless 900 s per OS. These deliberately conservative engineering guardrails are NOT product SLAs; owner must review actual measurements and approve budgets. Browser/OS memory, real graphical latency and production ERP staging are not measured here (real Platform integration is post-Stable).

The combined job emits `manual-acceptance.template.json` with exact source, run, attempt, archive hashes and automated summary digest; all rows start NOT RUN. Windows/macOS graphical host, NVDA/VoiceOver, native Chrome/Firefox/Safari, six products, both themes and languages. For each case test the named feature, record OS/browser/version, device, scaling/zoom, tester, date, observed behavior, evidence relative path and SHA-256. Mark PASS only after actual execution. For unsupported scaling use the nearest supported setting and document it in notes; never mark untested requirements PASS. For keyboard cases verify Tab/Shift+Tab, Enter/Space, focus visibility and restoration; screen readers verify names, roles, states, errors, live status and reading order; review incomplete axe findings even if zero violations. No real records. Use separate test evidence for React and standalone Web. Record defects in issues #3/#4/#6/#12/#13.

Security review: reconcile SBOM/audit findings and pinned dependencies, validate no production credentials/data/endpoints, verify network and literal markup regression evidence, evaluate permission/environment/provenance and license/rollback/registry controls. Technical security evidence does not establish owner approval. The structural validator refuses missing/failed/duplicated/unknown cases, wrong candidate or missing/modified evidence; human review and release approval remain mandatory. Never put credentials in evidence. To validate filled records: `python 30_distribution/qa/prepare_br9_manual.py acceptance-summary.json manual-acceptance.json --evidence-root ./evidence`. No publication or signing from this workflow.
