Taktera Design System — v3.3 · техническая редакция

Дата: 22 ноября 2026. Статус: готовый пакет для технической оценки / внедрения после QA целевых приложений; не продуктовый релиз. Нормативная визуальная основа: Taktera Brand v3.2 (18.10.2026).

Что сохранено без редизайна

  • Геометрия фирменного знака (изгиб, круглая точка), контурные логотипы, EN/RU подписи, набор из шести направлений.
  • Исходные акцентные HEX каждого продукта в обеих темах, включая красный Fitness и жёлтый Travel.
  • Все исходные PNG, SVG и ICO v3.2 остаются в пакете, не заменяются экспериментальными версиями.
  • Брендбук PDF 14 стр. и HTML v3.2 остаются нормативным визуальным основанием и доступны в прежних местах.

Реализовано в v3.3

  1. Обновлён исходный 04_tokens/taktera.tokens.json: светлые/тёмные роли управления и текстовые роли холста; две уточнённые текстовые пары для Spa и Fitness.
  2. Добавлены отдельные семантические статусы success/info/warning/error и их фоны. Они не являются продуктовыми цветами и не меняют логотипы.
  3. 09_source/generate_tokens.py генерирует CSS, DTCG JSON и детальный отчёт контраста из одного исходного JSON.
  4. 11_design_system/taktera.components.css и 12_examples/preview.html показывают реальное использование токенов в двух темах для шести продуктов: формы, таблицы, навигация, KPI, уведомления.
  5. Добавлены компактные WOFF2 файлы Inter (3 статических начертания) с сохранением OFL.
  6. Подготовлены 09_source/rebuild_assets.py (переносимый SVG -> PNG/ICO экспорт, по умолчанию только в отдельную папку) и 09_source/release.py (проверки, SHA-256, ZIP).
  7. Отдельно создано обновлённое руководство по токенам, компонентам, внедрению и QA.

Не реализовано и НЕ заявляется готовым

  • Полная библиотеки готовых React/Avalonia компонентов, бизнес-логика, Storybook, Figma, автоматизированные E2E проверки приложений.
  • Переделка самих иконок под macOS / Dock / Windows, новые EN lockup SVG — требуют дизайнерского утверждения и ручной проверки малых размеров.
  • Экспорт окончательного брендбука как единого нового PDF v3.3: документ v3.2 сохранён + отдельное руководство расширений v3.3; не выдаём старый PDF за новый.
  • Печатная допечатная подготовка, регистрация товарных знаков, юридические проверки.
  • Визуальный QA всех возможных экранов, переходов, масштабирования и assistive technology. Отчёт содержит только проверенные автоматизированные пары.

Как изучить результат

  1. Открыть START-HERE.html без интернета.
  2. Открыть 12_examples/preview.html; переключить 6 продуктов и 2 темы, проверить клавиатурную навигацию.
  3. Прочитать 01-TOKENS-AND-COLOR.md, 02-COMPONENT-SPEC.md, 03-PLATFORM-IMPLEMENTATION.md, 04-QA-CHECKLIST.md.
  4. Проверить исходники и сборку: python 09_source/generate_tokens.py --check, python 09_source/release.py.

Управление изменениями

Брендовые цвета изменять только после дизайн-согласования. Новые семантические роли — рабочие значения v3.3, которые следует принять как базу UI после тестирования в продуктах. Все изменения дизайнерских мастеров имеют отдельную историю; техническая сборка не должна незаметно изменять логотипы.

01 · Токены, цвета и доступность

Источник истины и экспорт

04_tokens/taktera.tokens.json — редактируемый единый источник значений. Генерируемые файлы:

Артефакт Для чего
04_tokens/taktera.tokens.css Совместимые с исходным пакетом CSS-переменные и новые UI-роли
04_tokens/taktera.tokens.dtcg.json Выгрузка DTCG 2025.10 со структурированными значениями colorSpace/components/hex и dimension
10_documentation/COLOR-CONTRAST-v3.3.json Проверка конкретных непрозрачных пар sRGB на контраст

DTCG реализована как экспорт из единого Taktera JSON; HEX с прямым $value не используется. Стандарт: https://www.designtokens.org/TR/2025.10/format/ и https://www.w3.org/community/reports/design-tokens/CG-FINAL-color-20251028/.

Слои токенов

  • Brand: --tk-mark, --tk-accent, --tk-on-accent — для логотипов/кнопок; значения цвета продуктовой идентичности не менялись.
  • Content: --tk-text, --tk-muted, --tk-accent-text для светлой поверхности, --tk-accent-text-canvas для холста paper.
  • Layout: --tk-canvas, --tk-surface, --tk-border, --tk-control-border; декоративный бордер допускается слабым, но не используется единственной видимой границей поля.
  • Interactive: --tk-accent-hover, --tk-accent-pressed, --tk-focus-ring, disabled роли.
  • Semantic: --tk-status-success-*, --tk-status-info-*, --tk-status-warning-*, --tk-status-error-*.

Отдельная роль для цвета текста на холсте

В исходной палитре Spa #118569 на paper #F4F3EF — 4,13:1; Fitness #D52B35 — 4,48:1. Брендовые цвета остаются неизменными, для мелкого интерфейсного текста на paper вводятся:

  • Spa: --tk-accent-text-canvas: #0D755B (контраст приблизительно 5,09:1).
  • Fitness: --tk-accent-text-canvas: #BE2430 (приблизительно 5,43:1).

Для Travel жёлтый фирменный #D4A600 остаётся цветом точки/акцента, а UI-текст по-прежнему #806300. В остальных продуктах текстовая роль холста наследует согласованный UI-текст.

Контур элементов управления

Тема --tk-border (декоративный) --tk-control-border (значимый)
Светлая #D9DCDF #858A93
Тёмная #444A52 #8D939C

Пара #858A93 на paper даёт приблизительно 3,12:1; #8D939C на тёмной поверхности #22262B — приблизительно 4,92:1. Не используйте цветной shadow, placeholder или декоративный разделитель как единственный сигнал доступности компонента.

02 · Контракт компонентов Taktera UI (draft 0.1)

Это инженерная спецификация для будущих React и desktop реализаций. В taktera.components.css реализован только ограниченный HTML-прототип, а не полный production UI-kit.

Универсальные состояния

Состояние Контракт
default Ясная визуальная иерархия, текстовый доступный ярлык
hover Только pointer; не скрывает информацию от клавиатуры
focus-visible Трёхпиксельный focus ring с отступом 3 px; проверить на фактическом фоне
pressed Степень изменения фона выше, чем для hover; не меняет label
disabled Элемент не интерактивен; если причину нужно объяснить, дать доступную подсказку рядом
loading Сохранить ширину кнопки, aria-busy; предотвратить повторный submit; не оставлять без текста
invalid aria-invalid, сообщение ошибки привязано через aria-describedby
selected Не только цвет — выделение, маркер, aria-selected там, где применимо
success/error Текст и семантические токены, уведомление при необходимости через live region

Плотность UI

Компактный desktop режим не должен уменьшать контраст или фокус. Профессиональные таблицы и расписания допускают плотность выше маркетинговых экранов, но должны сохранять читаемость. Для touch — рекомендованная область 44 × 44 px, для компактного desktop — 32 × 32 px с отдельной QA-проверкой.

Типографика и локализация

Inter 400/600/700; body 14/21, helper 12/16, H1 30/36, H2 24/30. Для денег, чисел и времени — tabular numerals. Учитывать кириллицу, длинное название «путешествия», компактные боковые панели, локализацию системных сообщений, часовой пояс и региональные форматы чисел.

Для продуктовых команд

В Taktera Clinic, Beauty, Spa, Fitness и Travel отраслевые компоненты строятся поверх общей базовой библиотеки, без локальных копий Button, Input и Dialog. Специфические медицинские/финансовые/туристические сценарии должны проходить отдельную проверку бизнес-логики и регуляторных требований; визуальные токены их не заменяют.

03 · Интеграция и технические границы

Браузерные приложения

Добавьте CSS из 04_tokens/taktera.tokens.css и собственную библиотеку компонентов или начните с 11_design_system/taktera.components.css только как прототипа. Установите data-product и data-theme на одном корневом элементе — это предотвращает неоднозначное наследование при вложенных темах. Для каждого theme/product обновляйте путь к SVG через соответствующий готовый ресурс: CSS не перекрашивает SVG внутри <img>.

<html lang="ru" data-theme="light" data-product="clinic">
<link rel="stylesheet" href="/brand/04_tokens/taktera.tokens.css">
<img src="/brand/02_logos/products/ru/svg/clinic-ru-light.svg" alt="Taktera Клиника">
<button type="button" class="tk-primary tk-focus">Сохранить</button>
</html>

Этот фрагмент демонстрирует палитру, но классы .tk-primary/.tk-focus сами по себе не создают компонент и его поведение. В демо подключена дополнительная библиотека стилей.

Desktop и Avalonia

CSS-токены браузера нельзя считать готовыми ресурсами Avalonia. Для приложений на Avalonia следует построить генератор ResourceDictionary/DynamicResource из DTCG или исходного JSON. Для каждой комбинации 6 продуктов × 2 темы сформируйте независимые словари, выделите семантические роли, проверяйте DPI, масштабирование, клавиатуру, OS high-contrast и реальные системные иконки.

Нельзя автоматически переносить color-mix в XAML: в DTCG сохранены численные RGB-значения hover/pressed. Для Windows ICO уже есть 7 слоёв; macOS app bundles и ICNS требуют отдельного проверенного экспорта.

Источник / релиз

python 09_source/generate_tokens.py           # Создать CSS, DTCG, contrast
python 09_source/generate_tokens.py --check   # Проверить актуальность
python 09_source/release.py                   # Проверить пакет и создать ZIP
python 09_source/rebuild_assets.py --output ../_test_assets # Не трогает source

rebuild_assets.py требует Pillow + CairoSVG. release.py дополнительно требует Pillow, fontTools и pypdf. Для генерации WOFF2 необходим fontTools + brotli. Старые скрипты из v3.2 сохранены в 09_source/legacy_v3.2: они были жёстко привязаны к оригинальному компьютеру, не использовать их для новой сборки.

Границы воспроизводимости

Новый SVG->PNG/ICO реэкспорт независим от машины автора, но не выполняет оригинальную оптическую реконструкцию выбранного растрового знака из 08_reference (это отдельный дизайнерский процесс). Готовые SVG в 02_logos — фактические канонические векторы. 14-страничный брендбук v3.2 остаётся исходной публикацией; отдельное дополнение v3.3 описывает изменения. Изменение исходных SVG потребует согласования, ререндеринга и визуального диффа.

05 · Дорожная карта v3.3 → v4.0

Работы разделены на этапы и критерии приёмки. Перевод задач в трекер допускается после определения ответственных и целевого приложения.

Этап A. Инженерная база v3.3 (реализовано как пакет)

  • Источник токенов, отдельные цветовые роли, WCAG-расчёты, WOFF2, пример UI, контрольные суммы, независимая пересборка графических экспортов.
  • Критерий: release.py проходит; generate_tokens.py --check проходит; ручной smoke test демо 12 сочетаний без JS-ошибок; v3.2 logo masters сохранены.

Этап B. Дизайн-утверждение и UX QA (следующий гейт)

  • Подтвердить статус палитры UI (не бренда), поведение всех состояний и размеры control borders; визуально пройти desktop/mobile; принять дополнительные EN lockup и системные иконки по отдельному макету.
  • Критерий: дизайн-ревью всех тем, таблица замечаний, отсутствие high-severity дефектов и протокол контрастных состояний.

Этап C. Компонентная библиотека v4.0 alpha

  • Реализовать Button, Input, Select, Checkbox/Radio/Switch, Tabs, Navigation, Table, Pagination, Card/KPI, Dialog, Toast/Alert, Empty State, Skeleton.
  • Критерий: документированное API, Storybook / аналог, unit и accessibility tests, frozen visual snapshots, клавиатура и theme switching.

Этап D. Отраслевые модули

  • Реализовать расписание/бронь, карточки клиентов, визиты, фильтры/поиск, загрузку файлов, отчёты и диаграммы на базе общих компонентов.
  • Критерий: одно правило дизайна на всю семью, нет fork'ов базовых компонентов, утверждённые шаблоны ключевых экранов.

Этап E. Маркетинговая и визуальная система

  • Формализовать бренд-голос, motion, паттерны, фото/иллюстрации, письма, OG, презентации, печатные носители, правила продуктовой иерархии.
  • Критерий: утверждённые мастера EN/RU, спецификация размера и охранного поля, реальные шаблоны для каждого направления, коммерческое правовое ревью.

Этап F. Внедрение и эксплуатация v4.0

  • Выпустить platform adapters (Web + целевая desktop технология), версии токенов, автоматическую сборку из Git, логи изменений, migration guide.
  • Критерий: все тесты CI зелёные, сценарий rollback проверен, отдельные acceptance reports для Windows/macOS и основных браузеров.

Примечание: сроки, бюджеты и владельцы пока не определены; эту дорожную карту нельзя считать подтверждённым планом производства.
